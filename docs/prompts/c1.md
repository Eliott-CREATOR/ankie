## The gate this chantier exists to reach

**Eliott reviews 20 real cards on his iPhone.** Not a demo, not test data — his own vocabulary, in

## Step 1 — `packages/core`

The shared layer both the Worker and the web app import. This is what keeps one FSRS
implementation honest.

- Wrap `ts-fsrs` (v6): a `Scheduler` created from `settings.fsrs_params` when present, defaults
  otherwise, and functions to rate a card and produce its next state
- Shared types for cards, senses, review-log entries — matching the D1 schema exactly
- **The golden-file test.** Replay a fixed sequence of ratings through the scheduler and assert the
  exact resulting intervals against a committed fixture. Any future `ts-fsrs` upgrade that silently
  changes scheduling gets caught here. This is the most valuable test in the project.

**CHECKPOINT 1** — show me the FSRS wrapper and the golden test. Commit.

## Step 2 — Seed the real words

`data/seed-words.csv` holds 50 words: `word, pos, translation_fr, example_sentence, domain, register`.

- A seed script that loads it into `lexemes`, `senses`, and one **recognition** card per sense
- `lemma_norm` = lowercased, unaccented — the dedup key
- `example_sentence` goes into `senses.source_context`
- **Idempotent**: running it twice must not duplicate anything
- Commit `data/seed-words.csv` itself — it was left untracked at the end of C0
- Run it against both local and remote D1

**CHECKPOINT 2** — show me a query proving 50 lexemes, 50 senses and 50 cards exist remotely, and
one full card row. Commit.

## Step 3 — The API

Two routes on the existing Worker. Small, boring, correct.

- `GET /api/due` — cards due now, ordered, respecting `settings.daily_new_limit` and
  `daily_review_limit`. Returns everything the front end needs to render a card in one call: no
  N+1, no second round trip.
- `POST /api/review` — accepts `{cardId, rating, reviewedAt, durationMs}`, runs FSRS, updates the
  card and appends to `review_log` **in one transaction**. The review log is append-only; never
  update a row in it.
- Reject invalid ratings and unknown card ids explicitly. Do not swallow errors — the C0 gate bug
  was exactly that mistake and it is the one failure mode this project cannot afford.

**CHECKPOINT 3** — show me both routes exercised against the deployed Worker with real card ids.
Commit.

## Step 4 — The review screen

One screen. This is the thing Eliott will look at a hundred times a week, so the brief is **how
little can be on it**.

**Card front:** the word, large. The context sentence beneath it, smaller and lighter — available
if he wants it, not shouting. Nothing else.

**Tap anywhere to reveal.** Back adds: French gloss, English definition, and the source sentence
with the word emphasised.

**Four rating buttons** — Again, Hard, Good, Easy — in a row at the bottom.

**Progress:** a quiet count, "12 / 23". No rings, no streaks, no animation.

**Empty state** when the queue is done: one line, no confetti.

### Design tokens — set these now, they are painful to retrofit

```css
font-family: -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
```

- **iOS type scale**: 17px body, 22px title, 13px caption. Not arbitrary sizes.
- **44px minimum height on every tap target.** The four rating buttons especially — this is the
  single biggest difference between feeling cheap and feeling right.
- **`padding-bottom: env(safe-area-inset-bottom)`** on the button row. `viewport-fit=cover` is
  already set, so this works — without it the buttons sit under the home indicator.
- Generous line-height on the context sentence; it gets read half-asleep.
- Light and dark both defined as tokens on `:root`, dark via `prefers-color-scheme`. Dark mode is
  its own palette, not an inversion.

```css
-webkit-tap-highlight-color: transparent;
overscroll-behavior: none;
user-select: none;
touch-action: manipulation;
```

Those four are what separate an app from a web page. `touch-action: manipulation` removes the
300ms double-tap-zoom delay — the thing nobody can name but everybody feels.

**CHECKPOINT 4** — deploy it and give me the URL. Commit.
